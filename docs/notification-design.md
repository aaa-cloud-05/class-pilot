# 通知の仕様（検討結果・未実装）

最終更新: 2026-09-06 ／ ステータス: **提案。ユーザーの承認待ち。まだ実装していない。**

現在コードに入っている「24h / 3h / 1h のプリセット3種」は、要件を決める前の**仮置き**。
ユーザーからも「今の実装は仮でしかない」と明言があった。以下は UX から考え直した設計案。

## 現行仕様の問題（実装前に潰すべき点）

1. **課題ごとに1通なので洪水になる。** 実ユーザーで18コース・93課題。締切が重なる週は
   1日に何通も届き、読まれなくなる。通知アプリが死ぬ典型パターン。
2. **深夜に飛ぶ。** 締切が翌2:00なら3時間前は23:00、24時間前は前日2:00。寝ている時間に届く。
3. **「3時間前」は行動を促さない。** レポートは3時間では終わらない。救済にはなっても
   着手のきっかけにはならない。
4. **締切基準の相対時刻は生活リズムと無関係。** 学生が見るのは朝の通学中と夜。
5. **0件の日にも送る設計だと解除される。** 「今日は課題がありません」を毎日送るのが一番嫌われる。

## いちばん重要な指摘

[product-brief.md](./product-brief.md) のくさびは
「**WebClass は通知もタスク表示も無いので、存在ごと忘れて見落とす**」。

だとすると本当に効くのは締切通知ではなく、**「新しい課題が出たこと」を知らせる通知**。
存在を知らなければ締切通知も意味がない。**ここが現行実装に完全に抜けている。**

## 提案する3本立て

| | いつ | 内容 | 役割 |
|---|---|---|---|
| **① 新着** | 取り込みで新規を検出した直後 | 「WebClassに新しい課題が3件」 | **くさび**。見落としを直接防ぐ |
| **② 朝のダイジェスト** | 毎朝 7:30（1日1通） | 「今日2件・明日1件・今週5件」 | 習慣化。開く動機をつくる |
| **③ 直前救済** | 締切3時間前・未提出のみ | 「〇〇があと3時間」 | 最後の砦 |

**②が主役、①がくさび、③が保険。** 個別の「24時間前」は②に吸収されるので**廃止**する。
これで通知数が `93件 × 3通` から **実質1日1〜2通**になる。

## 併せて必須の要件

- **静かな時間（22:00〜7:00）は送らない。** ①③はこの窓を避けて次の朝に回す
- **0件の日は送らない。** ダイジェストは中身があるときだけ
- **提出したら以降の通知を止める**（予約済みメールのキャンセル。[backlog.md](./backlog.md) の未対応項目）
- 設定は「新着 / 毎朝 / 直前」の3トグル + 静かな時間。**プリセット3種は廃止**

## 実装上の効き目（重要）

**この仕様なら cron は1日1回で足りる。**

- ② は時刻固定（7:30 JST = 22:30 UTC。現行 cron は 21:00 UTC = 6:00 JST なので近い）
- ③ はメールの予約送信（Resend の `scheduledAt`）で正確に届く
- ① は取り込み時に発火（`after()` の仕組みが既にある）

→ **Web Push のために必要だった「15〜30分間隔の外部 cron」が不要になる。**
[release-checklist.md](./release-checklist.md) の A' の 🔴 項目は、この仕様を採るなら消える。

## 実装するときに触る場所

- `src/lib/server/notification-logic.ts` … プリセット定義と `computePendingNotifications`
- `src/lib/server/notify.ts` … チャネルごとの送信（`canSchedule` の仕組みは流用できる）
- `src/lib/server/email.ts` … ダイジェスト用のテンプレートが新たに要る
- `prisma/schema.prisma` … `NotificationSetting` に quietHours と3つのトグル。`preset` は廃止
- `src/app/settings/page.tsx` … プリセットUIをトグルに置き換え
- 新着検出は `syncWebClassAssignments` / `syncClassroomAssignments` の `creates` を数えれば取れる

## メールと Push の違い（実装済みの前提知識）

| | メール(Resend) | Web Push |
|---|---|---|
| 独自ドメイン | **必要**（有料プランでも免除されない。DNS の話なので） | 不要 |
| 通数制限 | 100通/日・3,000通/月 | なし |
| **予約送信** | **できる** | **できない**（送った瞬間に届く） |
| 時刻の精度 | 正確 | cron の実行間隔で決まる |
| iOS | そのまま届く | ホーム画面に追加した PWA のみ（16.4+） |

ユーザーの方針は「**メールを主軸にする**」。Push はおまけ。
この差は `computePendingNotifications` の `canSchedule` で吸収済み。
詳細は [architecture.md](./architecture.md) の「チャネルの違い」を参照。
