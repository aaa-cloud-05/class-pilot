## 進め方

1. `/mock` にダミーデータで動く画面を作る（API・DB には一切触れない）
2. ユーザーが実機（スマホ・PC）で触り、配色やレイアウトを直す → 繰り返す
   - よく変える項目は、画面右端の「調整」パネルでその場で切り替えられるようにしてある
3. 確定したら `DESIGN.md` を書き、トークンと部品を本番に移し、画面ごとに PR で置き換える
4. 置き換えが終わったら `src/app/mock/` と `globals.css` の `@import "./mock/ui-tokens.css"` を消す

## 決定事項（2026-09-16）

- OG 画像は別の AI が作ったもので、**UI の参考にしない**
- メインカラーは **#2F6BFF 系の鮮やかな青**、または **Vercel 風の白黒灰**。モックで両方を比べる
- **ダークモードを設定から選べる**ようにする（自動 / ライト / ダーク）
- **モバイル優先で、PC 用のレイアウトも作る**
- タブ構成は任せる。ただし**今ある機能を1つも減らさない**（下の対応表で確認する）

## スキルの使い分け

| 場面 | 使うもの | 理由 |
|---|---|---|
| 配色・書体の候補出し、UX ルールの確認（タップ領域・ナビ・フォーム・ダーク時のコントラスト） | **ui-ux-pro-max** | 製品 UI 向けのルール集と検索がある。アプリ画面の良し悪しを判定する物差し |
| 既存画面の「AI っぽさ」監査、仕上げ前のチェック | **tasteskill: redesign-existing-projects** | 既存コードを 監査 → 診断 → 修正 の順に進める手順になっている |
| モノクロ方向の味付け | **tasteskill: minimalist-ui** | 白黒＋細線＋余白の作法 |
| 公開向けのページ（ログイン画面・将来のトップページ） | **tasteskill: design-taste-frontend** | LP・マーケ面が本来の守備範囲。アプリの一覧画面には向かない（本人がスコープ外と明記） |
| 全画面の最終チェック | 両方 | tasteskill の「AI っぽい表現の禁止リスト」＋ ui-ux-pro-max の Pre-Delivery Checklist |

tasteskill から採用するルール（アプリ画面にも効くもの）: アクセント色は1つだけ固定・角丸の体系を1つに固定・
ボタンの文字と背景のコントラスト確認・装飾だけの色付きドットを使わない（状態を表す点は可）・
意味のないアニメーションを入れない・`prefers-reduced-motion` 対応・ライト/ダーク両方を最初から作る。
採用しないルール: lucide 禁止（プロジェクトが既に依存しているので継続）、ランディング用のヒーロー/ベント規則。

# v2（2026-09-21〜）：目指す体験の言語化と、作り直しの方針

v1（`/mock`）は「機能の置き場所」は良かったが、**見た瞬間に立ち位置が分からない**・
**色とアイコンが多くてうるさい**・**動きがなく平坦**だった。v2（`/mock-v2`）で作り直す。
v1 は残す。全体構成（3タブ・PC の3カラム・設定のグループ分け）は変えない。

## 1. 目指す体験（北極星）

> **大学生は「1週間」単位で生きている。開いた瞬間に「今週のどこにいるか」が分かること。**

`docs/product-brief.md` のビジョン（「大学生の『今週』をぱっと把握でき、毎日開きたくなるダッシュボード」）を、
画面の言葉にするとこうなる。**開いて3秒で、次の3つに答えが出ている**こと。

| 問い | 画面での答え方 |
|---|---|
| ① 今週はあとどれくらい残っている？ | **残り件数を最大の文字で1つだけ**。提出済み◯/◯ を細い進捗バーで |
| ② 山場はいつ？　もう越えた？ | **曜日ごとの負荷を7本の細いバー**で。今日に印。過ぎた日は薄く |
| ③ 次に手をつけるのはどれ？ | ヒーローの最後の行に**「次にやる1件＋残り時間」**を置き、そこから開ける |

そのうえで「一文」を添える（例：**「山場は明日。今日は1件だけです。」**）。
数字を読んで解釈する作業を、アプリ側が肩代わりする。これが「便利なダッシュボード」と
「毎日開きたくなるダッシュボード」の差になる。

**開きたくなる仕掛け**は、派手な演出ではなく次の3つ。
- 開くたびに**進捗が目に見えて動く**（バーが伸びる・数字が変わる）
- チェックを付けた瞬間に**手応えがある**（スプリングで弾み、進捗が即座に追従する）
- **文が状況に合わせて変わる**ので、今日の意味づけが毎日違う

## 2. v1 の何を直すか

| 指摘 | 直し方 |
|---|---|
| 3枚のカードが横並びで色違い。読まないと分からない | 廃止。**「今週」ヒーロー1つ**に統合。大きい数字は1つだけ |
| アイコンが多すぎる／複数色（設定・通知） | 設定行の**色付き角丸アイコンを全廃**。アイコンは単色（ink-3）で、ナビと操作にだけ使う |
| アニメーションが無く平坦 | **Motion（旧 Framer Motion）**を入れる。入場・チェック・シート・タブに限定して使う |
| コースの色は意味があるのか | **一覧から色を外す**。色は「状態と時間」に予約する（今日＝アクセント／期限切れ＝赤文字／提出済み＝薄く） |
| PC で何を見ればいいか分からない・全部が並列 | **視覚的な重みを4段階**に固定：①ヒーローの数字 ②次にやる1件 ③リスト ④サイドバー・補助 |
| 温度感（Vercel は冷たすぎ、今は散らかっている） | 白ベース＋ほぼ無彩色＋**アクセント1色だけ**。面は白、地は薄グレー、線は細く。影は原則なし |
| shadcn らしい作りになっていない | **shadcn/ui を実際に入れる**。トークンは shadcn の変数名（`--background` 等）を `[data-ui2]` の中で再定義して使う（本番化がそのままできる） |

## 3. ビジュアルの決め（初期値・モックで調整する）

- 地 `#FAFAFA` / 面 `#FFFFFF` / 押下・入れ子 `#F4F5F6` / 線 `#E8E9EB`
- 文字 `#0C0D0E` / 補助 `#5B6169` / 注記 `#8A9099`
- アクセント `#2F6BFF` は **主ボタン・選択中・今日・進捗の塗り・フォーカス**のみ
- 期限切れは**赤い文字だけ**（赤い背景は削除ボタン以外で使わない）。提出済みは薄いグレー＋チェック
- 角丸：操作 10px / カード 14px / シート 20px。影はシートとメニューだけ
- 文字：本文 15–16px・行間 1.7／見出し 17px／ヒーローの数字 40px（tabular）
- 行の高さ 60–64px、余白はスマホ 20px・PC 32px

## 4. 動き（Motion）

`MotionConfig reducedMotion="user"` を土台に、次の5か所だけ。
1. 入場：ヒーローの数字カウントアップ（0.5s）→ 進捗バー → 曜日バー（40ms ずつ）→ リスト（30ms ずつ・上位6行）
2. チェック：スプリングで弾む → 行が薄くなって並び替え（layout）→ 進捗バーが追従
3. シート：下からスプリング（bounce 0.1）
4. タブ・セグメント：`layoutId` でインジケーターが滑る
5. 数値の変化：件数が変わるときだけ差分アニメーション

## 5. スコープ外（今回はやらない）

- 初回の人向けの導線づくり（設定項目の一本化・10分でフルセット）。別途やる。

## 6. v2 の実装メモ（2026-09-21）

- 置き場所：`src/app/mock-v2/`（v1 の `src/app/mock/` はそのまま残す）。URL は `/mock-v2`
- トークン：`src/app/mock-v2/ui-tokens.css`。**shadcn の変数（`--background` `--primary` など）を
  `[data-ui2]` の中で上書き**しているので、確定したらこの値を `:root` / `.dark` に移すだけで本番化できる
- **shadcn/ui を導入**（`components.json` / `src/components/ui/*`。base は radix、preset は nova）。
  CLI が本番側も書き換えたので、次は手で戻した：`src/lib/utils.ts` の `cn`（外部パッケージ依存に
  変えられていた）、`--font-sans` の自己参照、`--radius` の変更、重複した `@import`
- **Motion（`motion` パッケージ）を導入**。`MotionConfig reducedMotion="user"` を親に置き、
  入場（ヒーローの数字・棒・リスト）、チェックのバネ、シートの上下、タブの下地移動に限定して使う
- Motion の公式スキル（`~/.claude/skills/motion`）と MCP（`.mcp.json` の `motion`）も入れた
- ポータル（`Dialog` / `Drawer` / `DropdownMenu`）は body 直下に出てトークンの範囲外になるため、
  シートは自前実装のまま（Motion でドラッグして閉じられるようにした）。使っているのは
  Button / Switch / Skeleton と、トークン体系
- 色の使い方：アクセントは**主ボタン・選択中・今日・進捗・フォーカス**のみ。赤は**期限切れの文字**と
  削除ボタン。状態が「問題なし」のときは色を出さない（同期ランプは新しいときは点を出さない）

# v3（2026-09-22〜）：海外 SaaS の数値に合わせて作り直す

`/mock-v3`。v1・v2 は残す。**決めごとはすべてこちらで固定**する。

## 1. 実物から測った数値（研究メモ）

ブラウザで実際の DOM と computed style を見て取った値。

| 参考 | 取った内容 |
|---|---|
| **Vercel Geist**（`/geist/button`, 変数） | ボタン高さ **32 / 36 / 40px**、文字 **14px / weight 500**、角丸 **6px**（`--geist-radius`）、遷移 **0.15s cubic-bezier(0.4,0,0.2,1)**、影なし。灰色の階調（線 `#ebebeb` / 文字 `#171717` / 面 `#fafafa`）、赤 `#da2f35`、青 `hsl(212 100% 48%)` |
| **shadcn/ui blocks（dashboard-01）** | サイドバー＝薄い灰、本文＝白。カードは「薄い灰＋1px の線」。行 40px 前後、状態は小さなアイコン付きバッジ |
| **Supabase Docs** | UI 文字 13–14px、補助 12px、サイドバー項目 13px、遷移 0.15s。アクセントは登録ボタンと現在地だけ |
| **Amie** | 左に細いレール＋一覧、右に本文。一覧の行は 11–12px で非常に詰まっている。件数は右端に薄く |
| **Notion カレンダー** | ミニ月表示には点を置かない（今日＝塗り、選択＝薄い丸）。予定は左に色の縦線＋文字 |
| **Resend / motion.dev** | 1つの見出しだけ特別な書体・巨大サイズにして「格」を作る。ボタンは小さく、色は1つ |

**v2 が野暮ったかった理由**：文字 15–16px・ボタン 44–52px・角丸 10–20px と、**全部が一回り大きかった**。
上の実測どおり**一段階小さく・角丸を締める**と、それだけで空気が変わる。

## 2. 決めたこと（もう変えない）

### 色
- 面：本文＝白、サイドバーと囲み＝`#fafafa`、線＝`#ebebeb`。**影は使わない**
- 文字：`#171717` / 補助 `#757575`
- **青 `#0068d6` は「操作」だけ**：主ボタン・選択中・今日・フォーカス・リンク
- **状態は色で語る（1行に1色まで）**
  - 提出済み＝**緑のチェック**（`#3f9950`）
  - 期限切れ＝**赤の文字**（`#da2f35`）
  - 24時間以内＝**橙の文字**（`#a45c00`）
  - それ以外の未提出＝色なし（灰の輪郭）
  - **不明（WebClass で多い）＝色なし・点線の丸**。色を足さない代わりに、ホームに
    「未確認 ◯件を確認」を出し、シートでまとめて提出済み/未提出を選べるようにした
- 緑は「完了」専用。青と役割が被らない

### 数（あふれたときどうするか）
- **月グリッド（PC）**：1セルに最大3件（点＋課題名）。超えたら「ほか◯件」。セルは 104px
- **月グリッド（スマホ）**：点を並べない。**1〜2件＝点 / 3件以上＝短い棒**の2段階にして、
  色はその日でいちばん急ぐ状態。正確な数は読み上げと下のリストで出す
- **週の棒（ホーム）**：その週の最大で正規化するので何件でも形は崩れない。
  最大が6件以上のときだけ、いちばん多い日に数字を添える
- **日のリスト**：省略しない（スクロール）

### 大きさ
- ボタン：PC 32 / 36 / 40px、スマホは1段大きく（40 / 44px）。文字 13–14px・weight 500
- 角丸：操作 6px（`--radius` 8px の md）、囲み 8px、シート 12px
- 行：PC 42px、スマホ 52px。文字は 14px（スマホは 15px）、補助 13px、注記 12px
- 遷移 150ms。バネはチェックと下地の移動だけ

### はじめて使う人（作り直した）
- `/mock-v3/start`：**Google → WebClass → 通知** の3ステップ。各ステップに**比較表**を置き、
  「ログインすると何が増えるか」「WebClass の3つのつなぎ方の違い」が読めばわかる
- ホームには**カード型の案内を置かない**。1行の細い帯（`セットアップ 2/3`）だけ
- 設定 › 接続：Classroom と WebClass の**状態と操作**。WebClass は
  「取り込み（ブックマークレット）／自動取り込み（PC）／URL（開くボタンの行き先）」を表で区別
- 設定 › ヘルプ：**表3つ**（ログインの有無・WebClass の3つ・通知の種類）＋よくある質問。
  ヘルプも設定の2ペインの中に置き、別画面に飛ばさない

## 3. 画面
ホーム／カレンダー／通知／設定（概要・接続・通知・コース・アカウント・ヘルプ）／セットアップ／ログイン／取り込み。
PC は「左サイドバー＋本文」。ホームは**課題を選んだときだけ**右に詳細を開く（常時2カラムにしない）。

# v4（2026-09-22）：v2 と v3 の中間で確定させる

`/mock-v4`。**これを本番化の土台にする。** v2 の「ホームの分かりやすさ」と v3 の「SaaS らしい質感」を混ぜ、
サイズは v3 より少しだけ大きくする（v3 は目を細めるほど小さかった）。

## 0. サイズの基準（v2 / v3 / v4 の比較）

| 項目 | v2 | v3 | **v4（確定）** |
|---|---|---|---|
| 行のタイトル | 15–16px | 14px | **15px** |
| 補助テキスト | 13–14px | 13px | **13px** |
| 注記・ラベル | 12–13px | 12px | **12.5px** |
| リストの行の高さ（スマホ / PC） | 68 / 60 | 52 / 42 | **56 / 48** |
| ボタン（小 / 中 / 大） | 36 / 44 / 52 | 32 / 36 / 40 | **32 / 36（スマホ40） / 40（スマホ44）** |
| 角丸（操作 / 面 / シート） | 10 / 14 / 20 | 6 / 8 / 12 | **8 / 10 / 14** |
| ヒーローの数字 | 40px | 26px | **32px** |
| ページ左右の余白（スマホ / PC） | 16 / 32 | 16 / 24 | **16 / 24** |
| アイコン | 18–20px | 16px | **16px（ヘッダーは18px）** |
| 面の色 | 地=灰・カード=白 | 地=白・囲み=薄灰 | **v3 と同じ（地=白 / 囲み=#fafafa / 線=#ebebeb）** |

調整パネルに**密度（コンパクト / 標準 / ゆったり）**を足し、実機で最終決定できるようにする。

## 1. ホーム（v2 の構成＋v3 の質感）

| 決めること | どうする |
|---|---|
| ヒーローの主役 | **「未提出 ◯件」を大きい数字（32px）**で。v2 の分かりやすさを採用 |
| 進捗 | その下に細いバー（提出済み＝緑／期限切れ＝赤／残り＝灰）と `7 / 12 提出` |
| 曜日の負荷 | 7本の棒（下＝提出済み・上＝未提出、今日＝青、過ぎた日の未提出＝赤）。週内の最大で正規化 |
| 一文 | 「山場は明日。今日は1件だけです。」など状況の言語化（v2） |
| 次の1件 | ヒーロー下端に1行（課題名・科目・残り時間）。ラベルは付けない |
| 未確認 | ヒーロー内に「未確認 ◯件を確認」リンク → まとめて確認シート |
| 同期の状態 | ヒーロー右上に `Classroom 3分前 ・ WebClass 1日前`（文字のみ）。押すと同期シート |
| リスト | **グループごとのカード**（v2）。細い罫線の羅列はやめる。見出しはカードの外に 12.5px |
| グループ | 期限切れ / 今日 / 明日 / 今週 / それ以降 / 期限なし |
| 提出済み | 各グループの末尾に「提出済み ◯」の折りたたみ（既定は閉じる） |
| 並び替え・表示切替 | **置かない**（締切順固定。v2 のトグルは分かりにくかった） |
| PC | 課題を選んだときだけ右に詳細。未選択なら一覧を広く使う |
| 空 | アイコン＋1行＋「セットアップを開く」 |
| 読み込み | 行スケルトン5本 |
| エラー / 再ログイン | 1行の帯＋ボタン（カードにしない） |

## 2. リストの行

| 決めること | どうする |
|---|---|
| 左 | 丸チェック（18px）。提出済み＝緑の塗り、不明＝点線、その他＝灰の輪郭。当たり判定 40px |
| タイトル | 15px。2行まで（スマホ）／1行省略（PC） |
| 科目 | スマホ＝タイトルの下に 13px。PC＝右寄りの列（xl 以上でのみ表示） |
| 締切 | 右端 13px。期限切れ＝赤／24時間以内＝橙／その他＝灰。文言は「2日遅れ」「あと3時間」「明日 23:59」「金 23:59」「9/28 23:59」 |
| 通知オフ | 小さなベルの斜線アイコン |
| タップ | 行＝詳細を開く／丸＝提出済みの切替（トースト＋取り消し） |

## 3. カレンダー（v2 の構成）

| 決めること | どうする |
|---|---|
| 切替 | 週 / 月のセグメント＋前後ナビ＋「今日」 |
| 月（スマホ） | 日付＋印（1〜2件＝点／3件以上＝短い棒、色はその日でいちばん急ぐ状態） |
| 月（PC） | 課題名を最大3件＋「ほか◯件」。セル高 104px |
| 週（スマホ） | 日付ストリップ（7日）＋選んだ日のリスト |
| 週（PC） | 7列に課題を並べる（列はスクロール） |
| 期間の進捗 | カレンダーの下に「この月 7 / 12 提出」＋細いバー（v2 にあったものを戻す） |
| 今日 / 選択 | 今日＝青、選択＝塗り、両方＝青の塗り |
| タップ | 日＝下のリストを切替／課題＝詳細 |

## 4. 同期（作り直し）

| 決めること | どうする |
|---|---|
| サイドバーの同期カード | **廃止**。1行のテキストボタン `同期 3分前` に |
| ヘッダーの更新アイコン | **廃止**（Classroom 専用なのに全体更新に見えるため） |
| 同期シート | Classroom＝「今すぐ更新」ボタン／WebClass＝「取り込み方法」リンク。**別物として並べる** |
| 表記 | 「更新」は Classroom、「取り込み」は WebClass と、言葉を分ける |
| 鮮度の色 | 問題ないときは色を出さない。古い＝橙、切れている＝赤 |

## 5. 設定（接続とヘルプを一本化）

**設定 › セットアップ**（1ページ・上から順に実行）。各ステップはチェック付きの折りたたみカードで、完了したら畳む。

| 順 | ステップ | 中身 |
|---|---|---|
| 0 | 進捗 | 「3つ中2つ完了」＋細いバー |
| 1 | Google でログイン | 1行の説明＋**表（ログインで増えること）**＋ボタン。完了後は「接続中・3分前に同期」 |
| 2 | WebClass をつなぐ | **表（3つのつなぎ方の違い）**／ブックマークレットの手順（端末タブ）／自動取り込み（Tampermonkey・トークン）／WebClass の URL（用途を明記） |
| 3 | 通知をオンにする | プッシュ・メール・ブラウザのスイッチ＋タイミング＋**表（通知の種類）** |
| 4 | コース（任意） | 表示と通知をコースごとに |

設定トップは **セットアップ / 通知 / コース / アカウント / ヘルプ(FAQ)** の5つ。
ヘルプは FAQ と安全性の説明だけにする（手順はセットアップに集約）。

## 6. ログイン・取り込み

| 画面 | どうする |
|---|---|
| ログイン | 中央1カラム。ロゴ → 見出し2行 → Google ボタン（白地＋枠＋公式マーク） → 「ログインせずに使う」 → 価値3行（WebClass に通知・締切前に知らせる・1週間が見える） → 法務注記。PC も中央寄せで余白を取る |
| 取り込み中 | ロゴ＋進捗バー＋3ステップのチェック（受け取り／整理／保存） |
| 取り込み完了 | 「12件を取り込みました」＋内訳（新規◯・締切変更◯）＋「ホームで見る」 |
| 取り込みエラー | 推定原因＋「もう一度」＋「手順を見る」＋エラーコードは小さく |

## 7. そのほかの決め

| 項目 | どうする |
|---|---|
| 課題の追加 | ＋（ヘッダー／サイドバー）→ シート。課題名・科目（候補チップ）・締切（今日/明日/1週間後/なし）・提出状況 |
| 課題の詳細 | 科目／締切＋残り／取得元／提出状況の3択／「◯◯で開く」／編集・通知オフ／削除（確認つき） |
| 不明の扱い | 詳細に「WebClass から取れなかった」の一文。ホームからまとめて確認 |
| 通知ページ | 今日／昨日／それ以前。未読＝青い点。「すべて既読」 |
| 文言 | 「次にやる」→ラベルなし、「◯日超過」→「◯日遅れ」、「完了しています」→出さない、ボタンは動詞で終える |
| ヒントテキスト | 入力欄の下に 12px の注記だけ。色は muted のみ。長い説明はカードの外に出す |
| アニメーション | 入場（数字・棒・リスト）、チェックのバネ、シートの上下、切替の下地移動、件数の変化。150–350ms |
| 調整パネル | 密度・ライト/ダーク・和文フォント・データ状態・ログイン・セットアップ完了 |
